# lodging_pos

Front desk + admin system for a lodging that charges **per bed, per night, checkout 10:00**.
One Flutter codebase: **Windows** build = front desk (offline-first), **Android/web** builds = admin (online).

- Product requirements and acceptance criteria: `docs/prd.md`
- Database schema: `docs/schema.md`
- Business rules (BR-1 to BR-13), refund lifecycle, statuses, required test cases: the `lodging-rules` skill in `.claude/skills/lodging-rules/` — load it before any task that touches stays, payments, refunds, pricing, beds, shifts, occupancy or access control.

## Stack

- Flutter (stable), Dart 3
- State: `flutter_riverpod` · Navigation: `go_router`
- Local database: `drift` + `drift_flutter` (`sqlite3` 3.x bundles SQLite via build hooks; `sqlite3_flutter_libs` is obsolete)
- Passwords: `bcrypt` · IDs: `uuid` · Receipts/reports: `pdf` + `printing`
- Cloud (sprint 2): Supabase (PostgreSQL, auth, row-level security)

## Project structure

`flutter create` owns the platform folders (`android/`, `windows/`, `web/`); don't restructure them. All app code is organised feature-first inside `lib/`:

```
lib/
├── main.dart            # the desk (Windows)
├── main_owner.dart      # the owner's phone app (Android, web): features/owner_app
├── app/                 # router, theme, shell, role guard
├── core/
│   ├── database/        # drift tables, database.dart, migrations
│   ├── audit/           # writeWithAudit: business rows + audit_log + outbox in ONE transaction
│   ├── sync/            # cloud sync: SyncEngine, SyncStore, Cloud (Supabase), CloudWrites, PulledRows
│   ├── clock/           # Clock service — the only source of "now"
│   ├── auth/            # session, password hashing
│   └── money/           # KES formatting
└── features/<feature>/
    ├── domain/          # pure Dart: models + business rules. No Flutter, no database imports.
    ├── data/            # repositories: read/write via core/database and core/audit
    └── presentation/    # screens, widgets, Riverpod providers
```

Features: `auth`, `shifts`, `setup`, `guests`, `bed_board`, `stays`, `payments`, `receipts`, `housekeeping`, `backup`, later `inventory`, `expenses`, `reports`, `dashboard`.
`test/` mirrors `lib/`. Create a folder only when writing its first real file.

## Conventions (non-negotiable)

- **Money** is whole KES stored as `int`. Never `double`.
- **Time** is stored in UTC, displayed in Africa/Nairobi. Never call `DateTime.now()` outside `core/clock`; inject the `Clock` so tests control time.
- **IDs** are UUID v4 strings on every synced table. Every synced table has `id`, `created_at`, `updated_at`, `device_id`.
- **Single write path.** Repositories never write to drift directly; every insert/update goes through `AuditWriter.writeWithAudit(action:, userId:, body:)` in `core/audit`. In one transaction, for each synced row the body writes with `w.insert` / `w.update`, it also writes an `audit_log` row (that row's before/after, tagged with the action) and `outbox` rows for both. Build rows with the companion's `.insert(...)` so business fields are checked at compile time. `id` defaults to a new UUID (pass your own to link rows in the same transaction). The writer stamps `created_at`, `updated_at` and `device_id` on insert, and `updated_at` and `device_id` on update (never `created_at`); their client defaults throw, so an insert that bypasses the writer fails. Every audit row of one call shares an `operation_id`. Audit and outbox rows are written as each row is written, so nested calls keep write order; await every write (un-awaited ones are awaited before commit, and the handle throws once the call returns). Triggers reject direct updates that don't move `updated_at` and any delete of stays, payments, charges, refunds, refund decisions, voids or audit_log. Use `w.now` for business timestamps. Events that change no rows (`user.login`, `user.login_failed`) use `recordEvent`. If any part fails, nothing is saved. **One exception:** rows the sync pull brings from the owner's side are written by `PulledRows.apply` (`core/sync/pulled_rows.dart`) as they are, with no audit or outbox rows (their own audit rows come with them; they are never pushed back). `test/policy/single_write_path_test.dart` fails the build if anything else writes to the database outside the writer, `core/database/`, the backup's file copy and sync's own local bookkeeping (`sync_state`, `outbox`).
- **Audit actions** are named `entity.verb`: `stay.check_in`, `stay.extend`, `stay.late_charge`, `stay.check_out`, `payment.create`, `refund.request`, `refund.approve`, `refund.reject`, `refund.pay`, `void.create`, `shift.open`, `shift.close`, `bed.mark_clean`, `housekeeping.assign`, `price.update`, `room.create`, `bed.create`, `user.create`, `user.disable`, `user.change_password`, `user.login`, `user.login_failed`, `user.auto_lock`, `user.lock`, `user.reset_password`, `settings.update`, `room.update`, `room.deactivate`, `room.reactivate`, `bed.update`, `bed.deactivate`, `bed.reactivate`, `category.create`, `category.update`, `housekeeper.create`, `housekeeper.update`, `housekeeper.deactivate`, `housekeeper.reactivate`, `user.enable`, `guest.create`, `guest.update`, `payment.print` (a receipt printed or saved; later ones say COPY), `housekeeping.reassign` (the open task's housekeeper changed; the audit keeps old and new), `housekeeping.cancel` (closing a bed or room cancels its open cleaning task; the bed stays not cleaned), `backup.create` and `backup.failed` (daily local backups, through `recordEvent`), `refund.print` (a REFUND receipt printed or saved), `price.request`, `price.request_withdraw` (by the supervisor, or by the owner when closing the category), `price.approve` (with `price.update` in the same operation), `price.reject`, `sync.connect`, `sync.reconnect`, `sync.first_upload`, `sync.clock_warning` (the PC clock more than 5 minutes off the server's, once per episode; through `recordEvent`), `user.password_from_cloud` (the desk takes the owner's password changed on the phone, after the cloud confirmed it at sign-in). One call may record several actions (`w.insert(..., action:)`), all under one `operation_id`.
- **Append-only:** no update or delete code exists for `audit_log`. Stays, payments, charges, refunds and refund decisions are never edited or deleted by users; corrections are `voids` rows (`voidRecords` permission).
- **Refunds are calculated by the system** (`stays/domain/stay_rules.dart`: nights not yet started × the stay's locked price). No screen lets anyone type or change a refund amount. A refund is requested at early checkout, approved or rejected by a user with `approveRefund`, then paid out once from an open shift (`features/refunds/domain/refund.dart`).
- **Payment methods** are `cash` | `paybill` for payments and refund payouts alike (`PaymentMethod`); screens, receipts and reports label `paybill` as "M-Pesa" (`PaymentMethod.label`).
- **Occupancy is never stored.** Derive Available / Occupied / Overstay from active stays + clock (see the skill).
- **Business rules live in `domain/`** as pure functions with unit tests. Screens never calculate prices, times or statuses.
- **Permissions (BR-13):** every protected action is checked through the one permission map in `core/auth/permissions.dart` (`Permission` enum → allowed roles) with `can(user, p)` / `requirePermission(user, p)` (throws `NotPermitted`). Never compare roles (`role == Role.supervisor`) anywhere else; `test/policy/no_role_checks_test.dart` fails the build otherwise. Writes take the acting `UserAccount` and call `requirePermission`; routes need theirs too (`Routes.permissions` in `app/gate.dart`, setup routes fail closed) and nav items declare one (`NavItem.permission`). Hiding a screen is never the only lock. A new role is added by editing only the map.
- **Roles** (since schema v6; `admin` was renamed): `owner` (sets prices and adds or closes categories, approves refunds, decides price changes, Today, manages supervisors, all reports and the audit trail; works without a shift; no front-desk permissions), `supervisor` (runs the desk: setup, receptionists, settings, voids, shift oversight, backups, and all front-desk work; asks the owner for price changes) and `receptionist`. First run creates the **owner** (`createFirstOwner`); the owner adds supervisors (Staff, `addSupervisor`), supervisors add receptionists. **Price requests:** the supervisor asks on Prices (`PriceRequestsRepository.request`, one open per category, `withdraw`); the owner decides on Prices or from Today (`decide`; approving changes the price at once, refused when stale); closing a category withdraws its request (`withdrawOnClose`, inside `closeCategory`). **Price edits** (desk and phone) are cloud-first through `change_prices` once connected: saved only over the price the owner started from (`PriceEdit.expected`), all or nothing; losing says where and when (`priceMovedOnMessage`); offline it is refused and nothing is saved locally. A change of more than 50% asks "Are you sure?" first (`isBigPriceChange`, one rule for both apps). A database with no owner shows a one-time "Create the owner's account" screen before sign-in (`SetupState.needsOwner`, `createMissingOwner`); no screen inside the app creates an owner. The owner's home is **Today** (`Routes.today`, `Routes.homeFor`; the bed board needs `checkIn`), built from `features/dashboard` (pure figures in `domain/dashboard.dart`, Figma "01 Today"). Staff rules judge an account by its role even when disabled (`roleAllows`). Tests: `env.createFirstSupervisor(setup)` makes the owner (`owner` / `owner-pass`, `env.owner`) by the real first run, then the supervisor. Nobody approves a refund they requested (`approveRefund` in `refunds/domain/refund.dart`). **Refunds (AD-7):** the owner decides on the desk (Today → `/owner/refund?id=`, `RefundsRepository.decide`, once); the desk pays approved refunds in Refunds (`/refunds`, `payRefund`, own open shift, `RefundsRepository.pay`: M-Pesa needs `payout_phone` and the code) and prints a REFUND receipt (receipt key `refund:<id>`, `refundReceiptKey`, through the same receipt screens; listed in Receipts). "Admin" still names the AD-x stories, the `/admin/...` setup routes, `admin_tables.dart` and the admin (owner's) app.
- Every screen and service must work with **no internet**.
- UI text in English, amounts shown as `KES 1,000`; dates `Thu 15 Oct`, times 24-hour `07:02` (`core/clock/nairobi.dart`).
- **Phones** use one rule in `core/contacts/phone.dart`: spaces and dashes ignored, `+254`/`254` become `0`, only 07… and 01…, stored as 10 digits. Guests may also give an international number (`+` and 8–15 digits, stored as `+` and digits; the Kenyan rule is tried first); housekeepers are Kenyan-only. Lists show phones masked (`0722 ••• 310`, `+2567 ••• 678`); only a selected guest's card and the refund pay panel's "Send to" field (the number the M-Pesa refund goes to) show the full number. ID numbers always show masked (`••••3921`, `core/contacts/id_number.dart`). Audit entries keep only the compact masks (`0722•••310`, `••••3921`).
- **Design system** (spec: `docs/design.md`, artboards in `docs/design/`): raw colours, font sizes and font families live **only** in `lib/app/theme/` (`LodgingColors`, `LodgingType`, `Space`/`Radii`/`Sizes`); everything else reads them from the theme. `test/policy/no_raw_style_test.dart` fails the build otherwise. Fonts (Manrope, IBM Plex Mono, and Pirata One and IM Fell English SC for the wordmark only) are bundled in `assets/fonts/` with their sources recorded in its README. The brand is `LodgingWordmark` (sidebar, sign-in panel, shift top bar) with its sizes and gold shadow tokens in the theme (`wordmark_style.dart`); see design.md, "Brand". Shared widgets live in `lib/app/widgets/` (`LodgingWordmark`, buttons, `LabeledField`, `MoneyInput`, `SegmentedChoice`, `NightStepper`, `Note`, `StatusBadge`, `BedStatusTile`); working screens go inside `DeskShell` (`lib/app/shell/`), and each story adds its sidebar entry to `deskNavItems`. Every screen must render at **1366×768** without overflow (`test/app/screen_layout_test.dart`).
- **Settings** are read through `SettingsRepository` (`core/settings`). Every default lives in one map, `settingDefaults` in `core/settings/setting_defaults.dart`; the v1 seed writes it, any upgrade inserts keys still missing, and the reader falls back to it, so a new setting only needs an entry there.
- **Inactivity lock:** after `idle_lock_minutes` (default 10, range 1–60, one validator in `auth/domain/idle_lock.dart`) without a click, scroll, key press or mouse movement, the session signs out to the login screen (`user.auto_lock`); the sidebar's Lock screen button does the same at once (`user.lock`). Either way the shift stays open.
- **Shifts:** a receptionist must open (or continue) their shift after signing in. The owner never has one (no shift screen, no money at the desk). A supervisor works without one (`workWithoutShift`) and is never sent to the shift screen, but a payment always goes into the user's **own** open shift, so a supervisor taking one opens a shift first: check-in's "Open shift" goes to `/shift?then=…` and returns there (`Routes.shiftThen`, `redirectFor(returnTo:)`).
- **Widget tests and the database:** inside `tester.runAsync`, never write and then read again while the app is running: the write wakes the app's watched queries, which take the database lock in fake time, and the next read waits forever. Set up data (e.g. open the shift) before pumping the app.
- **Daily local backup** (`features/backup`, `docs/backup-restore.md`): on the Windows desk only, once the database check passes at start, then hourly if today (Nairobi) has none, after every shift close and on "Back up now" (`manageBackups`). `VACUUM INTO` a `.partial` file, checked (`integrity_check`, `user_version`), renamed to `lodging_pos-YYYY-MM-DD-HHMM.sqlite` in `<app support>\backups`; kept: today and yesterday in full, then the latest per day for 30 days; copied to the optional `backup_second_folder` (a missing drive is only noted on the Backups card). One at a time, in the background. The sidebar chip shows only for a failed main backup or none for yesterday and today. Tests set `env.backupFolder` (a temp folder) to turn backups on; widget tests wait for their real file I/O with `settleRealIo`.
- **Cloud sync** (`docs/sync.md`, `supabase/`): `SyncEngine` (`core/sync`) pushes the outbox in `seq` order once the owner has connected the desk (`connectDesk`, owner only) and the first upload (a resumable snapshot) is done; a refused row stops the queue. The owner's decisions, prices and price request withdrawals go to the cloud first through `CloudWrites` (repositories take `cloud:`), then are mirrored with `writeWithAudit(inCloud: {...})`, which stores their outbox rows as sent; `OwnerCloudSignInNeeded` makes the screen ask for the password (`withOwnerCloud`). Without `secrets.json` (and in tests unless `env.cloud` is set) there is no engine and everything is local. **The pull (sync-2):** after each push and every 30 s, `SyncEngine` pulls the owner's decisions, category prices and the phone's audit rows by `server_seq` (`sync_state` key `pull.after`), page by page, each page and the cursor in one transaction; rows already here are skipped; a clashing decision stops the pull ("Sync problem · details"), never the push. Every cloud function that writes a pulled row must take `pg_advisory_xact_lock(hashtext('lodging.owner_writes'))` before its first write (`supabase/tests/pull_test.sql` checks). Each pull also checks the PC clock: more than 5 minutes off warns on the pill ("PC clock 12 min slow · fix") until it's within 4; the offset goes in the heartbeat; nothing is blocked. Cloud schema changes are new files in `supabase/migrations` with pgTAP tests in `supabase/tests` (CI job `cloud`); the cloud mirrors the drift tables, so a drift table change needs its cloud migration too.
- **The owner's phone app** (`lib/main_owner.dart`, `features/owner_app`, `docs/sync.md` "The owner's phone"): online only, no database; it reads the cloud through `OwnerCloud.rows(table, columns, where:)` and decides through the same cloud functions (`decide_refund` with `server_time()`, a per-install `device_id` and its audit row). Every "now" on the phone is the server's (`ServerClock`, corrected by `server_time()` on every load). Tabs: Today, Money, Beds, Prices, More (owner-app-2 built Money, Beds and Prices from Figma "04"–"06"; owner-app-3 More: Shifts, Audit trail, Staff, read-only, and Change password; the figures are the desk's `dashboard/domain` functions, checked equal by `parity_test.dart`). It reuses the desk's domain rules and shared widgets (`today_cards.dart`, `refund_detail_body.dart`, `price_request_card.dart`, `BrandWordmark`), never `core/database`, `core/sync`, `core/audit` or `dart:io` (it must build for the web). **The owner's password** is also their cloud sign-in (`docs/sync.md`, "The owner's password"): every change is recorded first (`record_password_change`, `owner_password_changes`, pulled by the desk), then set; the desk refuses its own copy while the cloud has a later change and confirms the password with the cloud instead (`LoginService`, `OwnerPasswordCloud`, `sync_state` `password.cloud_at` / `password.desk_at`); the owner's "Change my password" (sidebar, `Permission.ownerCloudPassword`) is cloud-first. **Privacy:** every query names its columns (never `*`); audit `before_json` / `after_json` only for `auditDetailEntities` (no guest data; never `refunds`, whose rows carry `payout_phone`); guests are read only through the masked `owner_guests` view; ID numbers, full phones, `payout_phone` and `password_hash` are never downloaded; what it loads stays in memory only (secure storage holds just the session and the install id). `test/policy/owner_app_test.dart` and `FakeOwnerCloud` enforce this. Layouts must fit **360×640** and **412×915**. Release signing: `docs/release.md` (`android/key.properties`, never committed; CI builds with the debug key).
- **Secrets are never written in code, tests or committed config.** Keys (e.g. the Supabase URL and anon key in sprint 2) are passed at build time with `--dart-define-from-file=secrets.json` from an untracked file and read with `String.fromEnvironment`. The repo-root `.gitignore` blocks `.env`, `*.env`, `secrets*.json` and the Android upload key (`key.properties`, `*.jks`, `*.keystore`). Test passwords are made-up values for in-memory databases; `.gitguardian.yaml` excludes `lodging_pos/test/**` from secret scanning.

## Workflow

- One story per branch: `story/fd-4-check-in`. Story IDs (FD-x, AD-x) and acceptance criteria are in `docs/prd.md`.
- For domain rules, write the tests first.
- Before saying a story is done, check the Definition of Done:
  1. acceptance criteria pass
  2. works with the network off
  3. writes audit entries for its actions
  4. `flutter analyze` clean and `flutter test` passes
  5. runs in the Windows build
- **Schema v1 is frozen as of 16 Oct 2026. Every schema change is a numbered drift migration with a migration test. Never edit an applied migration.** The steps:
  1. Change the tables and bump `schemaVersion` in `database.dart`.
  2. Run `dart run drift_dev make-migrations`. It snapshots the new version in `drift_schemas/`, writes `database.steps.dart` and the test helpers in `test/drift/app_database/generated/`, and creates `test/drift/app_database/migration_test.dart` once.
  3. Add the generated step to `_upgrade` (`stepByStep(from1To2: …)`).
  4. Fill the migration test with real v1 rows and check they survive the upgrade. Its `AppDatabase(...)` calls need `clock:`.
  5. A new NOT NULL column gets a default or a backfill in its step. A new setting key needs only its entry in `settingDefaults`: after any upgrade, missing keys are inserted at their default (`insertMissingSettings`).
- **Column names must not clash with drift Table members** (e.g. no `table_name`, `row_id`, `primary_key`, `unique_keys`, `without_row_id`, `is_strict`, `custom_constraints`). Drift's generated schema code names its getters after the SQL columns, and a clash stops `database.steps.dart` from compiling.
- **Every upgrade** (`AppDatabase._upgrade`, details in `docs/schema.md`): the file is first copied to `lodging_pos.sqlite.v<old>.bak` (release builds too, newest two kept); then, with foreign keys off, the steps, a `PRAGMA foreign_key_check` (any report fails and undoes the migration) and the new version run in one transaction. The database always opens in WAL with `synchronous = FULL`. Schema is at **v9** (stay charges keep their category; stays keep their room number and bed label; cleaning tasks can be cancelled; a shift keeps its first count, close note and closer, and never changes once closed; users' roles are `owner` | `supervisor` | `receptionist`, the old `admin` now `supervisor`; an M-Pesa refund payout keeps the phone it went to; price requests and the owner's decisions; the local `sync_state`).
- **Database check at startup** (`core/database/schema_check.dart`): after any migration, the app compares the database file with the schema this build creates (SQL text normalized: whitespace, `"` quotes, spaces at `( ) ,`).
  - A debug build shows a "made by an older build" screen with a reset button. Reset renames the file to `lodging_pos.sqlite.bak-…` (never deleted) and starts fresh.
  - A release build shows an error, leaves the data untouched, and never offers a reset.
  - A file from a newer app version is refused.
- Commit messages: use the `commit-style` skill.

## CI

GitHub Actions (`.github/workflows/ci.yml`), Flutter pinned to the local version (**3.47.5**; change it there and locally together).

- **`CI / checks`** (Ubuntu, 15 min) runs on every pull request and every push to `main`, and is required to merge into `main`: `flutter pub get --enforce-lockfile`, `build_runner` then `git diff --exit-code` (committed generated code must be current), `drift_dev make-migrations` then no changed or new files (a schema change needs its numbered migration and snapshot), `dart format --set-exit-if-changed`, `flutter analyze --fatal-infos`, `flutter test --timeout 120s`. Run these locally before pushing; a red check blocks the merge.
- **`windows-build`** (Windows, 30 min) runs on pushes to `main` and on demand: `flutter build windows --release`, kept as a zip artifact for 14 days. Not required.
- **`owner-app-build`** (Ubuntu, 25 min) on every pull request and push: `flutter build apk --release -t lib/main_owner.dart` (debug-signed: `android/key.properties` must not exist there) and `flutter build web --release -t lib/main_owner.dart`. Nothing is kept or hosted. Not required.
- GitGuardian runs separately, unchanged.
- `.drift` files are checked out as CRLF on every OS (`.gitattributes`) because drift copies trigger SQL text, line endings included, into the schema snapshots. Don't change this rule without regenerating and reviewing all snapshots.
- If a golden test ever fails on Ubuntu only because of font rendering, tag it `golden`, skip that tag in `checks` and run it in `windows-build`; never move `checks` to Windows for that.
- Locally, don't run `flutter build windows --debug` while the app may be running from `flutter run`: they share the Debug folder. Use `--release` to check a build.
